# AX7Z020B OV5640 复位恢复说明

## 故障现象

AX7Z020B 下载 bitstream 和裸机应用后，HDMI 曾只能显示诊断彩条或无摄像头画面。
OV5640 的 I²C ID 可以正常读出，但 CSI 长包计数保持为 0。按 Reset 后故障表现会改变，
因此需要分别判断显示输出、摄像头输入和处理器软件状态。

## 定位结果

JTAG 寄存器检查确认 HDMI 内部输出链正常：

- FCLK0 和 PL 复位状态正常；
- 显示 VDMA MM2S 持续运行；
- 动态像素时钟已启动并锁定；
- VTC 输出为 1280×720 时序；
- 帧缓冲中存在完整诊断彩条。

异常时 CSI 长包计数为 `0 -> 0`，摄像头没有向接收端发送有效视频。CPU 同时停在旧版
应用的 `_exit` 循环。旧版应用只执行一次摄像头初始化和两秒诊断，然后从 `main()`
返回，无法在 Reset 或视频流停止后自动恢复。

这不是 DDR 内容丢失造成的 HDMI 黑屏。显示链和帧缓冲仍然可读，故障点位于摄像头
启动时序或 MIPI 输入链，旧版软件又没有恢复机制。

## 软件修复

恢复版应用包含以下修改：

1. 将 OV5640 配置与开始出图拆分为 `sensor_configure()` 和 `sensor_start()`。
2. 摄像头保持待机完成配置，采集 VDMA 启动后才打开 MIPI 输出。
3. 每两秒检查 CSI 长包增长、CRC 增量、VDMA 错误和帧完成状态。
4. 启动失败或运行中断流时，重新复位摄像头并初始化，最多尝试三次。
5. VDMA 复位增加超时，采集停止后才重画诊断彩条。
6. 初始化所有采集帧地址槽，并为 I²C 总线空闲等待增加超时。

## 板上验证

通过 JTAG 下载 `camera_recovery.elf` 后，CSI 长包计数在 500 ms 内从
`0x000638E0` 增加到 `0x000667B0`，CRC 错误保持为 0；摄像头 VDMA 状态为
`0x00011000`，帧缓冲内容也由彩条变成实时图像数据。这说明摄像头、MIPI、VDMA、DDR
和 HDMI 内部数据通路已经恢复。

如果这些状态正常而显示设备仍提示“无信号”，应检查 HDMI 物理链路。开发板必须连接
显示器或电视的 HDMI 输入端；普通电脑 HDMI 接口通常是输出端，不能接收开发板画面。
需要在电脑上查看时应使用 USB HDMI 采集卡。

## Reset 后的使用方式

普通处理器 Reset 后，PL 配置仍存在时，只需重新下载恢复版 ELF：

```powershell
& "$env:XILINX_VITIS\bin\xsct.bat" tools/run_camera_recovery.tcl
```

完全断电或 PL 配置丢失后，重新下载 bitstream、初始化 PS 并下载 ELF：

```powershell
& "$env:XILINX_VITIS\bin\xsct.bat" tools/program_camera_jtag.tcl
```

JTAG 下载不会在断电后保留。若要求不连接电脑自动启动且不使用 SD 卡，应把 FSBL、
bitstream 和恢复版 ELF 打包为 `BOOT.bin` 后烧录到板载 QSPI Flash，并将启动模式切换为
QSPI。启动模式跳线应以对应板卡版本的原理图和丝印为准。
