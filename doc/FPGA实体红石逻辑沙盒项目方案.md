# 基于 FPGA 的实体化红石逻辑沙盒与数字电路交互平台

## 1. 项目名称
**基于 FPGA 的实体化红石逻辑沙盒与数字电路交互平台**

英文名：**FPGA-Based Physical Redstone Logic Sandbox and Digital Circuit Interactive Platform**

## 2. 项目定位
本项目受到《Minecraft（我的世界）》红石系统和数字电路教学平台启发，尝试将游戏中的“红石逻辑”从虚拟世界搬到现实桌面。

玩家通过实体化模块搭建逻辑电路，例如拉杆、按钮、红石线、红石火把、中继器、比较器、红石灯、活塞、基础逻辑门、寄存器和计数器。FPGA 负责实时读取模块连接关系和状态，进行并行逻辑运算与时序仿真，并将信号传播结果实时反馈到实体 LED、执行机构和 HDMI 显示界面。

项目目标不是简单“用 FPGA 做 Minecraft”，而是：

> **把红石世界中的逻辑规则实体化，让玩家通过搭积木的方式亲手构建数字电路，最终搭建出 ALU、寄存器乃至简单 CPU。**

## 3. 项目背景
Minecraft 红石系统本身具有很强的数字逻辑属性。

| Minecraft 红石机制 | 数字电路概念 |
|---|---|
| 拉杆 | 输入信号 |
| 按钮 | 脉冲信号 |
| 红石线 | 信号连线 |
| 红石火把 | NOT |
| 双输入结构 | AND / OR |
| 中继器 | 延迟 / 缓冲 |
| 比较器 | 比较逻辑 |
| 红石灯 | 输出 |
| 活塞 | 执行机构 |
| 锁存结构 | SR Latch |
| 红石时钟 | Clock |
| 红石计算机 | CPU |

传统数字电路实验依赖面包板、EDA 仿真、逻辑芯片或 FPGA 开发板，对初学者有一定门槛。本项目希望利用“游戏化 + 实体化”的方式，让抽象逻辑变成可以看见、触摸和搭建的系统。

## 4. 核心创意
项目核心可概括为：

> **实体红石积木 + FPGA 并行仿真 + 可视化数字逻辑教学**

### 4.1 实体交互层
玩家在桌面上自由拼接：

```text
[拉杆] ── [红石线] ── [AND] ── [红石灯]
                         ↑
                      [按钮]
```

每个模块具有输入端口、输出端口、状态指示 LED、唯一模块 ID 和模块类型信息。

### 4.2 FPGA 逻辑仿真层
FPGA 维护整个红石网络：

```text
模块连接拓扑
     ↓
节点状态读取
     ↓
逻辑规则解析
     ↓
Tick Engine
     ↓
并行状态更新
     ↓
输出反馈
```

FPGA 实时计算当前输入状态、节点逻辑值、信号传播、Tick 延迟、中继器延迟、计数器状态和寄存器状态。

### 4.3 可视化层
HDMI 屏幕实时显示：

```text
当前节点数：28
逻辑模块：11
Tick：1024

Lever A = 1
Lever B = 0
AND = 0
XOR = 1
Propagation Delay = 3 Tick
```

同时显示拓扑、节点状态、波形、当前关卡和错误连接提示。

## 6. 建议硬件组成
### 6.1 FPGA 主控
前期原型不需要高端 FPGA，重点需要 GPIO、BRAM、PLL、HDMI/VGA、UART、SPI/I2C，可选 DDR。

### 6.2 第一阶段实体模块
建议先做：
1. 拉杆
2. 按钮
3. LED 红石灯
4. NOT
5. AND
6. OR
7. XOR
8. 中继器

后续再增加比较器、锁存器、D 触发器、计数器、MUX、寄存器、活塞和机械执行模块。

### 6.3 模块连接方案
可选：
- 插线式：简单稳定，最适合原型。
- 磁吸式：展示效果好，更像红石积木。
- 底板矩阵：最接近 Minecraft 网格世界，可自动识别模块位置。

比赛版建议最终采用：**底板矩阵 + 模块 ID 识别**。

## 7. FPGA 关键技术
### 7.1 矩阵扫描
通过行列扫描识别模块位置和状态，例如 8×8 Grid 共 64 个位置。

### 7.2 模块 ID 识别
可通过电阻编码、拨码、EEPROM、I2C ID 或 GPIO 编码识别模块类型。

### 7.3 红石 Tick Engine
```text
System Clock
     ↓
Clock Divider
     ↓
Redstone Tick
```

每个 Tick：
```text
读取上一状态 → 计算节点 → 处理延迟 → 写入下一状态
```

### 7.4 并行逻辑计算
多个节点可并行更新，这是 FPGA 相比普通 MCU 的核心优势之一。

### 7.5 状态 RAM
每个节点维护：
```text
Node_ID
Node_Type
Input_A
Input_B
Output
Delay
Position
```

### 7.6 波形记录
实时记录关键节点逻辑变化，并通过 HDMI 显示数字波形。

## 10. 项目创新点
1. **红石逻辑实体化**：把游戏机制转化为真实数字逻辑交互系统。
2. **游戏化数字电路教学**：学习路径从拉杆、逻辑门、加法器一路延伸到 ALU 和 CPU。
3. **FPGA 并行红石仿真**：硬件级实时计算大量节点。
4. **实体与数字同步**：实体电路与 HDMI 拓扑、波形同步显示。
5. **可扩展计算平台**：可加入自定义模块、多人协作、自动评分和 AI 提示。

## 11. 为什么必须用 FPGA
评委很可能会问“为什么不用 STM32”。

回答重点：
- 多节点并行计算；
- 确定性的 Tick 更新与延迟控制；
- 大量 GPIO；
- 可同时完成实时 HDMI 输出；
- 用户搭建的是数字电路，而 FPGA 本身就是数字电路。

> **系统的教学对象、仿真对象和实现平台三者高度统一。**

## 14. 风险控制
不要一开始就做完整 Minecraft 红石。

比赛初期目标控制在：

```text
实体模块
+
10~20 节点
+
逻辑运算
+
Tick
+
HDMI
```

这已经足够形成完整作品。CPU 应作为高级扩展，而不是 MVP 必须目标。
